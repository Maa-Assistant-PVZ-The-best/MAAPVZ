# SPEC —— SelectPlants 可选开关与无尽局外选卡（80 选卡）

> 事实来源：`agent/select_plant/custom_select_plant.py`
> 本文件记录**为什么这么改**与**验收标准**，实现以 `.py` 为准。

## 1. 背景

无尽局外「选择挑战植物」界面要选 **80 个植物**：

- 卡片**没有文字** → OCR 核对不可用；选中后打勾，打勾图也分不清 → 无核对手段。
- 模板为**手动截图**，在 `assets/resource/image/General/plant/plant_ref_endless/<品质>/<英文名>.png`，
  目录结构与 `plant_ref_card` 相同，`plant_lib.resolve_templates()` 直接复用。
- 截图严格对照 → 理论上不会漏选；漏了就是模板/阈值问题，**应当报错而不是默默跳过**。

## 2. 设计：同一个 custom，功能全部开关化

不新建 custom action。`SelectPlants` 增加可选开关，**缺省值 = 旧行为**，
现有 8 槽选卡（`无尽挑战_选取植物`，runtime 只注入 `{"植物列表": [...]}`）零影响。

| 参数 | 缺省 | 说明 |
|---|---|---|
| `无尽局外选卡` | false | ★ 80 选卡模式。**严格按「植物列表」顺序逐个选**（80 卡位按点击先后排布，顺序=优先级），当前帧优先找下一个、触底回顶重扫。隐含：不做核对 / 槽位检查 / 占位填充 |
| `核对` | true | false = 点击即成功，不做 OCR / 槽位核对 |
| `占位填充` | true | false = 结尾不做占位填充 |
| `槽位上限` | 8 | **仅单目标模式**：最多处理列表前几个（局外选卡不生效，80 个全选） |
| `尺度` | 单目标 0.85~1.15；局外选卡 `[1.0]` | 匹配多尺度。手截图同尺度，`[1.0]` 足够且快；抗截图偏差传 `[0.95, 1.0, 1.05]` |
| `局外点击间隔` | 150 ms | 无尽局外选卡模式每次点击之间的间隔 |
| `模板目录` | **按模式自动选** | 局外选卡缺省 `plant_ref_endless`，单目标缺省 `plant_ref_card`（都从 `__file__` 相对推算，打包后可移植；pipeline 里不要写绝对路径） |

触底判定（连续 `保底连续帧` 帧相似 ≥ `截图相似阈值`）、**动态回顶 = 本轮下滑次数 + 3**、
`最多重试` / `最多滑动步数`、协作式停止 —— 两种模式完全一致。

## 2.1 顺序优化（两种模式共有，2026-10）

**严格顺序 + 当前帧优先**：一个植物放完后**不再回顶**，下一个植物先看当前帧有没有 ——
有就直接点（连续几个植物同屏时一趟点完），没有才按「上一个植物的下滑屏数 + 3」回顶重扫。
这样：① 选取顺序严格等于「植物列表」顺序（先菜问、回顶后再大嘴花）；
② 同屏连续命中省掉大量回顶+全扫。单目标模式由 `_find_and_place` 的
`start_slide_count` 接力传递下滑屏数实现。

## 3. 无尽局外选卡循环（`_run_endless_select`，2026-10 改为严格顺序）

```
回顶(0+3)
while 还有未选中的 and retry <= 最多重试:
    截图
    只为「列表里第一个未选的」植物在 搜索roi 里 find_best
      -> 命中 -> 点击、弹出待选集、重截一帧（画面变了：打勾），留在原地找下一个
      -> 刚点完、当前帧没有下一个 -> **直接回顶**（不往下滑），从顶开始逐屏重扫
      -> 从顶扫描中仍没中 -> 滑一屏, slide_count++
        触底 或 slide_count 到上限 -> 回顶(slide_count+3), retry++, slide_count=0
全部选中 -> True；重试上限仍有剩余 -> 打印未选中名单 + False
```

要点：**点击后留在当前帧找下一个（不滑动）；当前帧找不到就直接回顶**，
从顶逐屏扫 —— 每个目标的查找起点都是可预期的顶部，和单目标模式同一套找法。

防呆：**按名除名**——点过的植物移出待选集，下一帧不再为它匹配，
已打勾的卡留在原位也不会被重复点击（重复点 = 取消选中）。
严格顺序下每帧至多一个目标，旧版的「同帧位置排他」不再需要。

> 旧版是「一帧多目标」：命中几个点几个，快但点击顺序由界面布局决定，
> 不等于「植物列表」顺序（80 卡位按点击先后排布，顺序就是优先级）——已废弃。

## 4. 性能

- `plant_match` 增加模板磁盘缓存（`_TPL_CACHE`）：局外选卡每帧对几十棵植物匹配，
  不缓存每帧都重新读盘解码 PNG。两种模式都受益，行为无变化。
- 局外选卡默认 `尺度=[1.0]`：84 模板 × 7 尺度每帧太贵；单尺度约 84 次 FFT/帧。

## 5. 接线（2026-10 已落地，runtime 按作业集 outer_pick 分流）

闸口节点 `无尽挑战_检查是否需要选植物`（OCR「选择挑战植物」）的 `next` 留空，
**由 `agent/jobset/runtime.py` 的 `_apply_outer_pick`（挂在 JobSetLoad）按作业集
`outer_pick.mode` 覆盖分流**（pipe 文件在 `06_Endless_80plant_choose/`）：

| mode | 闸口 next 覆盖为 | 后续链 |
|---|---|---|
| `auto` 按列表自动选取 | `无尽挑战_80植物界面_选项1_清空植物`（0601_1） | 清空 80 个 -> 切「全部植物」-> `无尽80植物编辑方案1_准备选择80个植物`（SelectPlants custom，植物列表由 runtime 注入）-> `无尽选卡_80个植物_确定` |
| `oneclick` 一键选取 | `无尽选卡_80个植物_一键选择`（0601_2，OCR「一键选择」点击） | -> `确定` |
| `confirm` 复用当前配置 | `无尽选卡_80个植物_确定`（0601_3，OCR「确定」点击） | -> `无尽挑战_识别开始战斗` |

- **植物列表注入**：`custom_action_param` 是整体替换，runtime 会先读
  `0601_80plant_choose_1.json` 节点现有参数（搜索roi/滑动/回顶/匹配阈值是实测值）
  合并后再注入 —— 改坐标只动 pipe 文件即可。
- auto 但 `plants` 为空（旧作业集/没配）-> 退化为「复用当前配置」直接点确定 + 告警，
  不会卡在选卡界面。
- 模板目录**不用写**：局外选卡模式缺省自动指向 `plant_ref_endless`
  （`plant_lib.ENDLESS_TEMPLATE_DIR`，从 `__file__` 推算，打包后可移植）。

## 6. 验收标准

1. 缺省参数（`{}` 或只传 `植物列表`）行为与改造前**完全一致**：
   核对照常、占位填充照常、8 槽上限照常、尺度 0.85~1.15。
2. `无尽局外选卡=true`：**植物列表给 80 个就一次选完 80 个**（不受 `槽位上限` 限制）；
   **严格按列表顺序逐个选**（当前帧优先找下一个，触底回顶重扫）；点过的植物不再点；
   触底回顶 = 本轮下滑次数 + 3；全部选中返回成功；重试上限有剩余返回失败并打印未选中名单。
3. `核对=false` 的单目标模式：点击即成功，不 OCR。
4. `占位填充=false`：结尾不点填充位置。
5. `槽位上限=N`：单目标模式最多处理列表前 N 个。
6. 顺序优化（两种模式）：一个植物放完后不回顶，下一个植物先看当前帧，
   有就直接点、没有才按上一棒下滑屏数 + 3 回顶。
7. 局外选卡模式下任务停止（`tasker.running=False`）能及时退出。
